# Технологічний стек проєкту

Документ сформовано на основі маніфестів залежностей, lock-файлів, конфігурації та фактичного використання технологій у коді. Версії нижче — зафіксовані у `composer.lock` або заявлені у `package.json`.

## Серверна частина

| Технологія | Версія | Призначення |
| --- | --- | --- |
| PHP | `^8.3` | Основна мова серверної частини; CI працює на PHP 8.3 |
| Laravel | `13.26.1` | Вебфреймворк, маршрутизація, ORM, міграції, черги, кеш і сесії |
| Livewire | `4.4.2` | Серверні реактивні компоненти та навігація без окремого SPA-фреймворку |
| Livewire Flux | `2.17.1` | Набір UI-компонентів для Blade/Livewire |
| Livewire Blaze | `1.0.18` | Оптимізація рендерингу Blade-компонентів |
| Laravel Fortify | `1.38.0` | Автентифікація, відновлення пароля, підтвердження email і 2FA |
| Laravel Passkeys / WebAuthn | PHP-інтеграція через Chisel `0.1.1`, JS-пакет `@laravel/passkeys` `^0.2.0` | Безпарольна автентифікація за допомогою passkeys |
| Blade | у складі Laravel | Серверні шаблони та single-file Livewire-компоненти |
| Eloquent ORM | у складі Laravel | Робота з моделями й базою даних |

## Дані та інфраструктура

- База даних за замовчуванням — SQLite (`database/database.sqlite`); конфігурація Laravel також допускає інші підтримувані драйвери.
- Сесії, кеш і черги в локальній конфігурації зберігаються у базі даних.
- Локальний запуск оркеструється Composer-скриптом через `concurrently`: Laravel dev server, обробник черги та Vite.
- Composer 2 керує PHP-залежностями; npm і `package-lock.json` — JavaScript-залежностями.
- `.nvmrc` задає Node.js 26, тоді як GitHub Actions наразі запускає CI на Node.js 22. Це розбіжність середовищ, яку варто узгодити.

Команда `composer test` очищує конфігураційний кеш, перевіряє форматування, запускає статичний аналіз і весь набір тестів.

## CI та автоматизація

- GitHub Actions запускає перевірки для push у `main` і для pull request.
- CI-середовище: Ubuntu, PHP 8.3, Composer 2 та Node.js 22.
- Dependabot щотижня перевіряє оновлення GitHub Actions.
- Laravel Sail присутній як dev-залежність (`1.67.0`), але Docker/Sail-конфігурація в корені проєкту не зафіксована, тому це доступний інструмент, а не підтверджений основний спосіб запуску.

## Архітектурний підсумок

Проєкт є монолітним Laravel-застосунком із серверним рендерингом Blade та реактивною взаємодією через Livewire. Він використовує готовий Livewire starter kit для автентифікації й налаштувань облікового запису, включно з email verification, двофакторною автентифікацією та passkeys. Окремого REST/GraphQL API або самостійного SPA-клієнта в поточній кодовій базі не виявлено.
